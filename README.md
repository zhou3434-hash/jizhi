# 寻万卷书

一个**简朴风格**的书籍查询网站。打开即是搜索栏，输入书名 / 作者 / ISBN，**左侧显示封面，右侧显示介绍**；首屏会随机推荐三本书。

> 本站只做**书籍信息查询与展示**，不提供在线阅读、不提供下载，外链均为书目信息页。

**开源与合规**：源码以 MIT 许可证发布（见 `LICENSE`）；书籍简介与封面等第三方内容不在该授权范围内，详见 [`THIRD-PARTY-NOTICE.md`](THIRD-PARTY-NOTICE.md)。
公开部署请关闭豆瓣源：`ENABLE_DOUBAN=0 node server.js`。

---

## 一、快速开始

```powershell
git clone <你的仓库地址> xunwanjuan
cd xunwanjuan
node server.js
```

然后浏览器打开 **http://127.0.0.1:8099/**

换端口：`$env:PORT=9000; node server.js`

> 必须通过本地服务器访问，不要直接双击 `index.html`。
> 直接以 `file://` 打开时浏览器会拦截跨域请求，且没有后端可分忧取数。

## 二、为什么需要这个本地服务器（重要）

这台机器的网络情况比较特殊，实测结论：

| 通道 | 结果 |
| --- | --- |
| 直连 `https://openlibrary.org` | 8 秒超时 / 连接被重置（被墙） |
| 直连 `https://www.googleapis.com` | 超时 |
| 直连 `https://book.douban.com`（国内） | **正常**（300ms 级） |
| 走本机代理 `127.0.0.1:7897` | **Open Library 200 OK**、豆瓣也通 |
| 浏览器直接请求国外书库 | 失败（`signal is aborted without reason`） |

所以架构是：**浏览器 ⇄ 本地 Node 服务 ⇄（自动选择直连或本机代理）⇄ 书库**。

`server.js` 启动时会自动探测本机代理端口（7897 / 7890 / 7891 / 10809 / 10808 / 1080 / 2080 / 8889 / 8080），
境外书库优先走代理、国内书库走直连，两条链路谁先成功用谁。

启动日志会明确写出当前出网方式：

```
寻万卷书 已启动: http://127.0.0.1:8099/
出网方式: 本机代理 127.0.0.1:7897（自动探测），直连失败时自动改走代理
```

**使用前请确认代理软件（Clash / V2Ray 等）已运行**，否则 Open Library 部分会取不到数据（豆瓣仍可用）。

## 四、数据源开关与开源说明

| 环境变量 | 默认值 | 说明 |
| --- | --- | --- |
| `PORT` | `8099` | 服务端口 |
| `HOST` | `127.0.0.1` | 监听地址 |
| `ENABLE_DOUBAN` | `1`（开启） | 设为 `0` 关闭豆瓣源，只保留 Open Library / Google Books 等开放接口 |

豆瓣没有公开的书目 API，其中文简介与封面来自公开页面解析，**适合本地个人查询**。
若把本站公开部署（公网服务、在线演示、作品集），请按上面的开关关闭该源；关闭后首屏随机推荐会同步停用（推荐书池依赖豆瓣源），检索与详情功能不受影响。

项目仓库中**不包含**任何抓取所得的数据快照：缓存只在服务进程内存里，重启即清空。
代码许可是 MIT，但书籍书名、简介与封面图片的著作权归原作者及出版方所有，不在 MIT 授权范围内。

## 五、数据源分工

| 数据源 | 用途 | 实测速度 |
| --- | --- | --- |
| **豆瓣** `book.douban.com` | **中文书主力**：书名/作者/年份/ISBN/封面/中文简介/评分/主题词 | 检索 ~0.4s，简介 ~1.5s |
| **Open Library** `openlibrary.org` | 全球书库、英文书、版本数、主题词、外文简介 | 检索 8~13s（走代理） |
| Google Books | 兜底（当前节点 TLS 不稳定，失败即自动跳过） | 经常失败，已加熔断 |

两个源的结果按书名合并去重，字段互补：一方缺封面/简介/ISBN 就用另一方的，中文简介优先，**豆瓣结果排在前面**。

## 六、功能说明

| 功能 | 说明 |
| --- | --- |
| 首屏推荐 | 打开即显示**随机三本书**（只有封面、书名、作者，不给简介），下方配一句勉励读书的谚语；点「换一批」重新随机，点封面直接查询该书 |
| 搜索栏 | 书名、作者、ISBN；回车或点「查询」；按 `/` 快速聚焦 |
| 检索范围 | 「中文书库（豆瓣）」「全球书库（Open Library）」，默认都开，可单独关掉提速 |
| 结果列表 | 左栏列表，点选即在右侧查看；可「收起」让详情占满整行 |
| 封面 | 左栏大图，走本地图片代理（豆瓣图床需 Referer，已在后端补齐）；失败自动换备用源，全失败显示简朴占位图 |

| 连接状态 | 顶栏实时显示「已连接本地后端 · 出网代理 xxx」或「未检测到本地后端」 |

## 七、接口一览（server.js）

| 接口 | 说明 |
| --- | --- |
| `GET /api/status` | 健康检查，返回探测到的代理地址与豆瓣源开关状态 |
| `GET /api/search/stream?q=词&db=1&ol=1` | **流式检索**（逐行 NDJSON）：快速源先发一帧，慢源到达再补一帧，前端边收边渲染 |
| `GET /api/recommend?n=3` | 首屏随机推荐：从 24 本精选书池随机取 n 本（只含封面/书名/作者） |
| `GET /api/search?q=词&db=1&ol=1` | 一次性检索（等全部数据源返回后合并），作为流式接口的兜底 |
| `POST /api/book` | 传回一本书对象，补全简介/评分/出版社等详情 |
| `GET /img?u=封面地址` | 封面图代理（带缓存、防盗链、跟随跳转） |
| `GET /api/clear` | 清空内存缓存并解除数据源熔断 |

内存缓存：检索结果 10 分钟、封面 24 小时、推荐书池 6 小时，因此**同一个词第二次检索是毫秒级**。
服务启动后自动预热推荐书池（3 并发，避免触发豆瓣限流），首屏推荐**约 50 毫秒**返回。

### 渐进式出结果（为什么检索不再需要干等）

豆瓣约 0.3 秒返回，Open Library 走代理要 8～15 秒。如果等两者都到齐再渲染，用户就要空等十几秒。
`/api/search/stream` 按「谁先到先发谁」的顺序推送两帧：

| 时刻 | 推送内容 | 页面表现 |
| --- | --- | --- |
| ~0.3s | 豆瓣结果（`done:false`，含 `pending`） | 立即显示结果列表与详情，提示「正在补充其他数据源…」 |
| ~8s | 合并后的完整结果（`done:true`） | 列表里追加全球书库条目，保留用户已选中的那本，不跳回第一条 |

实测：**首屏 252ms 可用**（原来要等 7281ms）。流是逐行 NDJSON，浏览器按行解析并保留跨块缓冲，
网络把 JSON 切成碎片也不会解析失败（已用每 7 字节一刀的方式验证）。

## 八、故障排查

| 现象 | 原因与处理 |
| --- | --- |
| 顶栏显示「未检测到本地后端」 | 没有通过 `node server.js` 访问，请用 http://127.0.0.1:8099/ |
| 状态在，但英文书搜不到 | 代理软件没开。开启后刷新页面即可 |
| `暂时无法连接书库` | 看顶栏：若已显示代理，说明代理节点本身不通，换节点或开启系统代理 |
| 中文有结果、英文没有 | 正常，Open Library 依赖代理；只勾「中文书库」也能用 |
| 检索很慢（首次 8~15 秒） | Open Library 走代理的固有延迟；关掉「全球书库」可降到 1 秒级 |
| 某个数据源突然不出现 | 该源连续失败 3 次会被**熔断 90 秒**（保护体验），之后自动恢复；访问 `/api/clear` 可立即恢复 |
| 首屏推荐空白 | 启动后需几十秒预热书池；也可能是关闭了豆瓣源（`ENABLE_DOUBAN=0`） |

## 九、开发自测

已随项目验证（离线桩数据 + 真实网络两套）：

- **后端回归全通过**：检索、豆瓣中文简介、封面真图校验、英文简介、缓存、无结果处理、无阅读入口
- **前端离线 27/27 通过**：首屏随机三本、谚语显示、换一批、点封面查询、骨架屏、流式首帧渲染、收尾合并保留选中项、后端不可用时的直连回退
- **流式专项全通过**：首帧/收尾帧时序、分块截断健壮性（每 7 字节切一刀仍能还原全部帧）、各数据源组合、异常输入
